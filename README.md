# Ya-Ca

<img src="plugins/ya-ca/assets/ya-ca.png" alt="Лист календаря с надписями 8 jun и .ics" width="104" />

Неофициальный плагин для работы с Яндекс Календарём в Codex. Он собирает повестку по всем доступным календарям одного аккаунта, находит свободные окна и планирует встречи. Почтовые приглашения проходят через Ya-Mail. Товарный знак «Яндекс» принадлежит ООО «ЯНДЕКС».

## Подключение

1. Скачайте архив Ya-Ca или клонируйте этот репозиторий. Распакуйте архив в постоянную папку. Windows-сборка с суффиксом `windows-x64` содержит Python и все зависимости. Для исходников и переносимого архива установите [uv](https://docs.astral.sh/uv/getting-started/installation/).
2. В Windows откройте `connect.cmd`. В Linux выполните `sh connect.sh`. Мастер откроет окно или перейдёт в терминал. Для текстового режима сразу запустите `connect.cmd --terminal` или `sh connect.sh --terminal`.
3. В мастере откройте страницу паролей Яндекс ID. Выберите нужный аккаунт и тип **Календарь (CalDAV)**, дайте паролю имя **Ya-Ca** и скопируйте его. Яндекс показывает пароль один раз. Он действует до отзыва. [Пароли приложений](https://id.yandex.ru/security/app-passwords) · [Справка Яндекс Календаря](https://yandex.ru/support/yandex-360/customers/calendar/web/ru/data-exchange/synchronization/sync-desktop)
4. Введите полный email, пароль CalDAV и часовой пояс. Для создания событий выберите «Чтение и редактирование». Мастер проверит доступ и покажет число найденных календарей. Пароль вводится только на вашем компьютере.
5. Если нужны приглашения, в конце мастера нажмите «Открыть мастер Ya-Mail». Подключите **тот же адрес** с разрешением отправки. Если он уже подключён в Ya-Mail с этим правом, дополнительный вход не требуется. В терминале используйте `ya-ca connect-mail --terminal`. В автономной Windows-сборке доступна команда `plugins\ya-ca\runtime\python.exe -m ya_cal.cli connect-mail --terminal`.
6. Из папки с этим README добавьте локальный каталог плагинов и установите Ya-Ca. После установки из исходников перезапустите Codex, чтобы он увидел команду `ya-ca` в PATH.

```sh
codex plugin marketplace add .
codex plugin add ya-ca@grebennikov-calendar
```

На Linux для графического окна нужен Tk. Для хранения паролей в графическом и текстовом режимах нужен разблокированный Secret Service в пользовательской D-Bus-сессии. Например, на Debian/Ubuntu это пакеты `gnome-keyring` и `dbus-user-session`. При запуске из SSH у мастера и процесса Codex должен быть доступ к одному пользовательскому хранилищу. В Windows используется системный Диспетчер учётных данных. Каждый аккаунт подключается отдельно.

## Примеры для Codex

- «Покажи, что у меня сегодня и завтра по всем календарям».
- «Поставь календарю “Студия” тип “рабочий” и приоритет 90, семейному — “личный” и 60».
- «Найди будущие занятия с тегом “дизайн” до конца декабря».
- «Найди на четверг час между 10 и 16. Если он свободен, поставь занятие, добавь тег “группа” и напоминание за 15 минут».
- «Пригласи Катю на согласованное время через Ya-Mail». Для отправки нужен адрес Кати. Контекст переписки и адрес можно найти инструментами подключённого плагина Ya-Mail.
- «Перенеси только занятие 8 июня на 11:00 и сообщи участникам». Для исходного письма с приглашением Ya-Ca также умеет читать календарное вложение по ссылке на письмо из Ya-Mail.

## Как работает планирование

Приоритет от 0 до 100 влияет на порядок событий с одинаковым началом. Тип календаря и приоритет хранятся у пользователя. Теги записываются в свойство iCalendar `CATEGORIES`. Поиск поддерживает заголовки, описания, места, адреса участников, теги и отбор по календарям. В повестке и поиске повторения показаны по отдельности. Для события на весь день дата окончания исключается из интервала.

Перед созданием и переносом Ya-Ca проверяет занятость во всех видимых календарях выбранного аккаунта. Пересечение возвращает занятые интервалы, запись можно разрешить отдельно. Свободные окна учитывают повторения, исключения, прозрачные события и отказы приглашённого. Для повторяющейся серии проверяются ближайшие 366 дней от начала новой серии или от текущего момента при правке уже начатой. Границы возвращаются в результате. Проверка занятости и запись в разные календари — отдельные запросы CalDAV. Другое устройство может занять время между ними. Изменение и удаление конкретного события защищены проверкой версии ETag.

## Встречи и почта

Ya-Ca использует Yandex CalDAV для календарных данных и исходящий модуль Ya-Mail для собственных встреч. Создание и перенос готовят письма iCalendar REQUEST, снятие участника и отмена — CANCEL, ответ на клиентское приглашение — REPLY. На сервере новые участники получают параметр `SCHEDULE-AGENT=CLIENT`. Встречи, для которых работает планирование самого сервера, сохраняют этот режим.

Когда пользователь просит уведомить участников, агент вызывает `send_notifications` после сохранения встречи. Очередь хранит отдельную запись для каждого получателя. Ответ SMTP показывает, какие адреса сервер принял или отклонил. При потере ответа Ya-Mail сохраняет Message-ID и останавливает автоматический повтор. Неподтверждённые изменения CalDAV проверяются по сохранённой метке. Очередь доступна через `list_notifications`; при повторе отправки используется прежний `change_id`. Если после сбоя владелец проверил календарь и изменение так и не появилось, осиротевшую подготовленную рассылку можно снять.

## Данные и отключение

MCP-сервер работает локально по stdio. Результаты запрошенных операций получает подключённый агент. Пароли CalDAV и Почты хранятся раздельно в системном хранилище. Локальная SQLite содержит настройки, адреса получателей, подготовленные уведомления и состояние отправки. После известного результата SMTP содержимое подготовленного письма удаляется из очереди Ya-Ca.

`ya-ca status` показывает подключённые адреса. `ya-ca disconnect EMAIL` удаляет локальный вход, настройки календарей и очередь этого аккаунта. Для полного отзыва доступа удалите пароль Ya-Ca в Яндекс ID. Почтовым доступом управляет Ya-Mail.

## Сборка и проверка

```sh
uv run --python 3.13 --with pytest python -m pytest -q
uv run --python 3.13 python scripts/package.py
```

Для автономного архива на Windows передайте `scripts/package.py --windows-runtime ПУТЬ` к чистой Windows x64 сборке CPython 3.13 от python-build-standalone. Каталог `dist` содержит архивы, wheel и SHA-256. Проверки выполняются на синтетических календарях и письмах. Вход в реальный Яндекс ID и доставка в почтовый ящик получателя требуют тестовых аккаунтов.
